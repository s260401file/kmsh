# 壹、文件目的與說明
本文件為「高雄市立民生醫院護理科電子白板系統」自建資料庫 **Whiteboard**（Microsoft SQL Server）之資料庫程式物件清冊。

- 經清點實際部署之資料庫，本系統**未使用預存程序（Stored Procedure）、使用者函數（Function）、檢視表（View）或觸發程序（Trigger）**。
- 資料存取一律由後端 API 於 **Repository 層以 Dapper ＋ 參數化 SQL** 封裝，SQL 隨原始碼版本控管、隨 API 佈署。
- 資料庫端僅保留宣告式物件：資料表、索引、以及隨結構腳本建立之預設值／檢查約束。
- 本清冊涵蓋：資料庫程式物件現況清點、設計說明、資料庫建置腳本（DDL）清冊、以及等同預存程序角色之「資料操作清冊（Repository）」。

# 貳、設計說明：資料存取採 Dapper 參數化 SQL
本系統之資料存取採「Repository 封裝 ＋ Dapper 參數化 SQL」而未採用預存程序，主要考量如下：

- **版本一致：** SQL 隨原始碼一同納入版本控管（Git）並隨 API 佈署，避免資料庫物件與程式版本分歧、便於回溯。
- **維護與測試：** 資料存取邏輯集中於 Repository 類別，語意清楚、易於維護與單元測試。
- **資訊安全：** 全面採用參數化查詢，杜絕 SQL Injection；任何新增／修改／刪除均先經授權過濾（MutationAuthorizationFilter）並寫入操作稽核（OperationAuditFilter）。
- **結構版本化：** 資料庫結構以 schema 版本腳本（可重複執行）管理，逐版套用；查詢邏輯不落於資料庫端，降低跨環境部署風險。

> 說明：若日後因效能或大量批次作業需導入預存程序，將循相同之 schema 版本腳本機制納管，並同步更新本清冊。

# 陸、結語
- 本系統資料庫端不含可執行程式物件（預存程序／函數／檢視／觸發程序）；資料存取邏輯集中於後端 Repository 層並以參數化查詢實作。
- 資料庫結構之建立與升級全數以版本化 schema 腳本納管；欄位層級定義詳見《資料表結構文件》，實體關聯詳見《實體關聯模型文件》。
- 日後如導入預存程序或其他資料庫程式物件，將更新本清冊並納入結構腳本版本控管。
