# 壹、文件目的與依據
本需求變更確認書依據「高雄市立民生醫院護理科電子白板系統」需求規格書（中華民國 115 年 02 月 09 日）、契約規定及系統需求確認書編撰，作為本專案執行期間及保固期間「需求變更」之管理、評估與確認依據。

- 系統需求確認書已確認第一階段系統總功能支數為 **31 支**；各階段之需求變更以系統總功能支數 **10%（約 3 支）** 範圍內為限，不另計費。
- **不含**健保署、國健署、衛生局及評鑑等主管機關來函要求之變更，該等變更不計入 10% 範圍。
- 每筆需求變更均以「需求變更確認單」記錄、評估影響，經雙方確認簽署後執行，並更新相關交付文件與功能支數追蹤表。

# 貳、變更管理原則
- **免計費範圍：** 各階段以系統總功能支數 10% 為限；超出部分之工作內容與費用另行議定。
- **排除項目：** 健保署、國健署、衛生局及評鑑等主管機關來函要求之變更，不計入 10% 免計費範圍。
- **回歸測試：** 任何變更完成後，須對受影響範圍執行回歸測試並記錄結果。
- **文件連動：** 變更後更新受影響之交付文件（系統需求確認書、資料表結構文件、實體關聯模型文件、使用者操作手冊、系統管理手冊、程式清單等）。
- **版本控管：** 變更之程式與資料庫結構隨原始碼版本控管，資料庫結構異動以版本化 schema 腳本納管。

# 參、變更處理流程
1. **提出：** 本院或廠商提出需求變更，填寫「需求變更確認單」載明變更內容與原因。
2. **評估：** 廠商評估對功能支數、時程、資源、測試範圍及費用之影響。
3. **確認：** 雙方就影響與處理方式確認並簽署；涉及超出 10% 或衍生費用者，另行議定。
4. **執行：** 依確認內容修改系統與資料庫，程式與結構納入版本控管。
5. **測試：** 完成後對受影響範圍回歸測試，記錄結果。
6. **更新：** 更新受影響之交付文件與功能支數追蹤表，納入下一次審查／驗收。
