# 壹、前言
本測試計畫書為本專案階段 3 之交付文件，依據需求規格書（中華民國 115 年 02 月 09 日）、系統需求確認書（KMSH-NWB-SRC-001）及契約規定編撰，載明本系統之測試目的、範圍、策略、環境、組織分工、進度、測試項目、通過準則與缺失管理，作為執行系統測試、使用者測試及據以撰寫測試報告書之依據。測試以系統需求確認書確認之功能範圍為基準；本文件經本院審查合格後據以執行。

# 貳、測試目的
- 驗證系統功能符合系統需求確認書所載之功能需求。
- 驗證與醫療資訊系統（HIS）及院方電子白板 API 之介接正確；未開放欄位之自建後台過渡資料顯示正確。
- 驗證權限管理、稽核軌跡、閒置自動登出等資訊安全需求。
- 驗證系統效能（線上查詢回應時間）與服務水準符合規範。
- 驗證響應式版面（RWD）於各尺寸裝置與指定瀏覽器之相容性。

# 參、測試範圍與對象
- **第一階段 4 個護理站**：W52 一般病房、ICU 加護病房、OR 手術室、ER 急診室之顯示端與後台管理功能。
- **共通與後台管理**：值班醫師排程、引用值班醫師顯示、頁首與檢視設定、帳號與權限管理。
- **介接**：HIS 引用資料表結構之落地資料、院方電子白板 API（手術／病床）、單一登入（SSO）／AD。
- **非功能需求**：效能、資訊安全、相容性、備份與回復。
- **不在本階段範圍**：洗腎室（第二階段）功能。

# 肆、測試策略與方法
## 一、測試層級
| 層級 | 說明 | 執行者 |
|---|---|---|
| 單元測試 | 個別程式模組／API 端點之邏輯驗證 | 廠商 |
| 整合測試 | 前後端、資料同步（ETL）與介接之串接驗證 | 廠商 |
| 系統測試 | 依測試案例對整體系統之功能與非功能驗證 | 廠商 |
| 使用者測試 | 由本院使用者及資訊人員共同操作驗證（階段 5） | 本院／廠商 |

## 二、測試類型
- **功能測試**：各站分頁功能、後台維護、資料新增／修改／刪除。
- **介接測試**：HIS 落地資料、院方 API 手術／病床、SSO／AD 登入。
- **效能測試**：線上查詢回應時間抽樣量測。
- **資訊安全測試**：權限授權、未登入異動拒絕、稽核軌跡、登入失敗紀錄、閒置自動登出、SSL。
- **相容性測試**：Safari、Edge、Chrome 及各尺寸裝置（RWD）。
- **回歸測試**：缺失修正或需求變更後，重測受影響範圍。

# 伍、測試環境
- 伺服器：Windows Server 2022、IIS 10、.NET 8、Microsoft SQL Server 2022。
- 前端：React 建置之網站，經由 IIS 部署；白板顯示端以資訊播放電腦連接 55 吋觸控顯示器。
- 瀏覽器：Safari、Edge、Chrome（最新穩定版）。
- 測試資料：以去識別化／測試資料進行；不得以真實病人資料進行破壞性測試；介接來源未開放欄位以自建後台測試資料驗證。
- 測試區與正式區分離，測試不影響正式作業。

# 玖、通過準則與驗收標準
- 各測試項目之預期結果均達成，且無**嚴重**或**重大**缺失未結。
- 線上作業查詢回應時間抽樣量測不超過 5 秒。
- 系統可用率符合：接獲通知 2 小時內連線處理、必要時 4 小時內到場、12 小時內回復正常運作。
- 權限、稽核軌跡、閒置自動登出、SSL 等資安需求驗證通過。
- 使用者測試由本院使用者確認功能符合作業需求。

# 拾、缺失管理
## 一、缺失分級
| 等級 | 定義 |
|---|---|
| 嚴重 | 系統無法運作或資料錯誤，影響作業無法進行 |
| 重大 | 主要功能異常，有替代方式但影響作業效率 |
| 一般 | 次要功能或顯示異常，不影響主要作業 |
| 建議 | 操作體驗或非功能性建議事項 |

## 二、缺失處理流程
- 測試發現缺失即記錄於缺失清單（編號、發現日、項目、等級、描述、狀態）。
- 依等級排定修正順序；嚴重／重大優先修正。
- 修正後由測試工程師回歸測試，通過後結案；受影響範圍一併回歸。
- 缺失統計與結案情形彙整於測試報告書。

# 拾壹、風險與因應
| 風險項目 | 可能影響 | 因應對策 |
|---|---|---|
| HIS 欄位未開放 | 介接項目無法以真實資料驗證 | 以自建後台測試資料驗證顯示邏輯，待開放後補測 |
| 測試資料不足 | 邊界情境涵蓋不足 | 依註記／狀態設計代表性測試資料 |
| 硬體到貨延遲 | 顯示端相容性測試延後 | 先於一般裝置驗證 RWD，硬體到位後補測 |
| 需求變更 | 影響測試範圍 | 以需求變更確認單管理，變更後回歸測試 |
