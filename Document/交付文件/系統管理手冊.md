# 壹、前言
本系統管理手冊為本專案階段 4 之交付文件，供本院資訊室及系統管理人員安裝、設定、維運及故障排除本系統之用，內容涵蓋系統架構、環境需求、部署程序、設定管理、資料庫管理、帳號與資訊安全、備份與還原、監控維運及版本更新。**本手冊不記載任何帳號密碼、金鑰等機敏資訊**，相關連線資訊由本院資訊室另行保管。

# 貳、系統架構
## 一、系統組成
| 元件 | 說明 |
|---|---|
| 後端 API | .NET 8 MVC Web API，提供白板顯示與後台維護之資料服務 |
| 前端網站 | React 建置之靜態網站（白板顯示端與管理後台畫面） |
| 資料庫 | Microsoft SQL Server，儲存介接落地資料與自建後台資料 |
| 資料同步工具 | 定時將院方電子白板來源資料清洗、落地至本地資料庫（ETL） |
| 目錄服務 | 本院 AD，供帳號整合與單一登入（SSO） |

## 二、部署拓樸
- 後端 API 與前端網站部署於本院 IIS（同機或分離皆可）。
- 資料庫可於同機或獨立資料庫主機。
- 白板顯示端以資訊播放電腦連接 55 吋觸控顯示器，以瀏覽器全螢幕開啟白板網址。
- 資料同步工具以排程於伺服器背景執行。

# 參、環境需求
- 作業系統：Windows Server 2022（含）以上（64 位元）。
- Web 伺服器：IIS 10（含）以上，並安裝 **.NET 8 Hosting Bundle**（含 ASP.NET Core Module）。
- 資料庫：Microsoft SQL Server 2022（含）以上。
- 前端建置環境（僅部署／更新時需要）：Node.js（供 React 建置），或使用已建置之靜態檔。
- 瀏覽器（顯示端）：Safari、Edge、Chrome。
- 系統內碼一律 UTF-8。

# 肆、安裝與部署
## 一、後端 API 部署
1. 於伺服器安裝 .NET 8 Hosting Bundle 並重新啟動 IIS。
2. 於 IIS 建立應用程式集區（No Managed Code）與網站，指向 API 發佈目錄。
3. 將 API 發佈檔（dotnet publish 產出）部署至站台實體路徑。
4. 設定連線字串與介接參數（見「伍、設定管理」）。
5. 啟動應用程式集區與網站，確認 API 可回應。

## 二、前端網站部署
1. 於建置環境執行前端建置（產生靜態檔 dist）。
2. 將 dist 內容部署至前端站台實體路徑（覆蓋舊檔）。
3. 確認 API 位址設定正確，白板與後台可正常連線。

## 三、資料庫建置
1. 於 SQL Server 建立資料庫。
2. **依序**執行資料庫結構腳本（schema 版本檔），套用時須以 **UTF-8** 執行（sqlcmd 加 -f 65001），確保中文正確。
3. 腳本具可重複執行特性；升級時僅執行新增之版本檔。
4. 確認資料表、索引、預存程序建立完成。

## 四、資料同步工具
1. 部署同步工具至伺服器並設定來源與目的連線（由資訊室保管）。
2. 以工作排程器設定定時執行（預設每數分鐘一次）。
3. 首次執行後確認落地資料表已產生並更新。

# 伍、設定管理
- **連線字串**：資料庫連線於後端設定檔維護；連線帳密由資訊室保管，建議使用最小權限帳號。
- **AD／LDAP 與 SSO**：設定目錄服務位址與整合參數；帳號異動之連動由服務帳號執行。
- **介接參數**：院方電子白板來源主機位址與存取金鑰由資訊室保管，設定於後端設定或同步工具設定中，**不得寫入原始碼或文件**。
- **應用程式集區身分**：後端集區以本院指定之服務帳號執行，該帳號須具備上傳目錄寫入權與目錄服務所需授權；不使用作業系統最大權限帳號。

# 陸、資料庫管理
- 資料表分兩類：**介接落地表**（由同步工具寫入）與**自建後台表**（由後台維護，多以單位代碼或病歷號為鍵，含建立／異動時間戳記）。
- 各資料表與欄位建立**中文欄位說明**（名稱、定義、屬性）。
- 結構異動採版本化 schema 腳本管理，逐版套用、可重複執行。
- 交付項目另含 **Table Schema 文件、E／R Model 文件、資料庫預存程序清冊**。
- 定期檢視索引與資料量，必要時進行維護作業。

# 柒、帳號與權限管理
- 帳號角色透過本院 **AD** 整合維護，並與 SSO 整合。
- 後台可建立、更名、停用帳號與重設密碼，並**連動 AD**；停用採停用方式（不實際刪除）。
- 權限採角色組合（role-based）之階層式授權，可依單位與功能授予不同使用者。
- **存取原則**：白板顯示端（GET）匿名可讀；任何新增／修改／刪除須通過登入授權，未登入之異動一律拒絕。

# 捌、資訊安全
- **稽核軌跡**：資料新增／修改／刪除記錄最後異動帳號與時間；記錄登入、登出、登入失敗超過三次等事件（含帳號、IP、時間）。
- **閒置登出**：使用者閒置達本院設定時間後自動強制登出。
- **傳輸安全**：對外服務支援 SSL 等安全性規格。
- **弱點與更新**：配合本院弱點掃描與入侵偵測修補；作業系統、資料庫及第三方元件之安全更新配合辦理，並每季進行漏洞修補。
- **防毒與資產**：配合本院既有防毒與資安資產機制。
- 依「資訊系統分級與資安防護基準」及本院 ISMS 辦理；參與人員簽署保密切結書。

# 玖、備份與還原
- **資料庫備份**：依本院備份政策定期執行完整與交易紀錄備份，異地或指定儲存留存。
- **檔案備份**：上傳圖片（佈告欄／避難圖／各科協助業務）等實體檔案一併納入備份。
- **還原**：依備份還原資料庫與檔案；定期配合本院辦理災難復原演練，驗證還原可用性。

# 拾、監控與維運
- 監看應用程式集區與網站運作狀態、事件檢視器與應用程式日誌。
- 監看資料同步工具執行結果與落地資料更新時間。
- 定期抽測線上查詢回應時間（規範不超過 5 秒）。
- 系統無法作業時，依服務水準：接獲通知 2 小時內連線處理、必要時 4 小時內到場、12 小時內回復正常運作。

# 拾壹、更新與版本部署
## 一、後端更新
1. 停止對應應用程式集區（釋放檔案佔用）。
2. 部署新版發佈檔至站台目錄。
3. 如有資料庫結構異動，先套用新增之 schema 版本腳本（UTF-8）。
4. 啟動應用程式集區，確認 API 正常。

## 二、前端更新
1. 建置前端產生新版靜態檔。
2. 部署（覆蓋）至前端站台目錄。
3. 顯示端如有快取，重新整理（Ctrl+F5）即可。

## 三、注意事項
- 更新宜於非尖峰時段進行，避免影響護理站作業。
- 變更前備份現行版本與資料庫，保留回復點。
- 維護中文資料一律經由系統畫面或 UTF-8 腳本，**勿以外部工具直接寫入非 UTF-8 字串**，以免中文變成問號。

# 拾貳、故障排除
| 症狀 | 可能原因 | 處理建議 |
|---|---|---|
| 白板顯示空白或無法連線 | API 集區停止或網站異常 | 檢查應用程式集區與網站狀態、事件日誌，重啟集區 |
| 白板資料未更新 | 同步工具未執行或來源異常 | 檢查排程與同步結果、來源連線 |
| 後台無法儲存（未授權） | 未登入或權限不足／逾時 | 重新登入並確認權限 |
| 中文顯示問號 | 以非 UTF-8 方式寫入資料 | 改由系統畫面或 UTF-8 腳本維護；修正既有資料 |
| 部署時檔案被佔用 | 集區未停止 | 先停止應用程式集區再部署，完成後啟動 |
| 資料庫連線失敗 | 連線字串或權限錯誤 | 確認連線設定與帳號權限（由資訊室保管） |

## 二、維運檢查清單
- 應用程式集區與網站為啟動狀態。
- 資料同步工具最近一次執行成功、落地資料時間正常。
- 資料庫備份最近一次成功。
- 稽核與登入紀錄正常寫入。
- 線上查詢回應時間符合規範。
