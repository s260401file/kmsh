# 貳、系統概述
## 一、系統架構
- 應用平台：**.NET 8** 以上，以 **MVC 架構**運作；程式語言 **C#**。
- 網頁前端：以 **React** 開發之 Web Based 前端，採**響應式網頁設計（RWD）**，版面適配各尺寸資訊裝置。
- 資料庫：**Microsoft SQL Server 2022** 以上。
- 伺服器：相容 **Windows Server 2022** 以上、**IIS 10** 以上（64 位元）。
- 系統內碼一律 **UTF-8**；瀏覽器支援 **Safari、Edge、Chrome**。
- 畫面採一致之功能鍵與畫面風格；輸入欄位具檢核與錯誤提示；代碼欄位提供下拉選單並可鍵盤輸入。

## 二、部署與瀏覽環境
- 後端 API 與前端網站部署於本院 IIS；電子白板以資訊播放電腦連接 55 吋觸控顯示器全螢幕顯示。
- 白板顯示端採定時輪詢自動更新，免人工重新整理即反映最新資料。
- 第一階段建置 4 個護理站：**W52 一般病房、ICU 加護病房、OR 手術室、ER 急診室**。

## 三、資料流與介接概觀
- 與醫療資訊系統（HIS）介接部分**引用其資料表結構定義**；HIS 結構異動時依約無償配合修改。
- HIS 尚未開放之欄位，先以**自建後台**登錄過渡，待院方開放後切換資料源，白板顯示不受影響。
- 手術／病床等院方電子白板資料經**同步機制（ETL）**清洗後落地本地資料庫，再供白板查詢，降低對來源系統之即時負載。

# 伍、系統設計
## 一、應用架構
- 採前後端分離：React 前端負責顯示與後台維護畫面；.NET 8 MVC 後端提供 Web API。
- 後端以 Repository 模式存取資料庫（Dapper），連線由連線工廠統一管理。
- 顯示端 API 一律匿名可讀（供大廳白板顯示）；新增／修改／刪除等異動須通過登入授權過濾，確保資料異動具身分依據。

## 二、模組與資料流
- 各護理站為「版面外框（Layout）＋多分頁（Tab）」結構，共用頁首、跑馬燈與分頁列。
- 白板資料來源分三類：（一）院方系統經同步落地之資料（病床、手術）；（二）自建後台登錄之過渡資料（檢查／會診、排班、佈告等）；（三）中央共用資料（值班醫師排程）。
- 顯示端定時輪詢後端聚合資料，未取得時保留前一次成功資料，避免畫面瞬間空白。

## 三、資料同步（ETL）
- 院方電子白板來源資料經同步工具清洗、轉置後落地本地資料表，供白板查詢，並定時更新。
- 同步流程具容錯與可重複執行特性，來源異動時僅需調整對照，不影響顯示端。

# 陸、資料庫設計
- 資料庫為 Microsoft SQL Server；各資料表與欄位建立**中文欄位說明**（欄位名稱、定義、屬性）。
- 資料表分為「介接落地表」與「自建後台表」兩類；自建表以單位代碼（UnitCode）或病歷號為鍵，具建立／異動時間戳記。
- 交付時另提供**系統 Table Schema 文件與 E／R Model 文件**、**資料庫預存程序清冊**（依契約階段 9 交付）。
- 資料之新增／修改／刪除於欄位內記錄最後異動之使用者帳號與發生時間，供稽核。

# 柒、介接需求確認
- **HIS 介接：** 引用 HIS 資料表結構定義；HIS 結構異動時無償配合修改；未開放欄位以自建後台過渡，開放後切換資料源。
- **院方電子白板 API 介接：** 配合介接高雄榮總電子白板相關程式或 API（手術、病床等），並依約配合高雄榮總、高市聯醫相關資訊作業與會議。
- **單一登入（SSO）：** 操作方式（資料、畫面、帳號、登入、更新機制）與本院 SSO 整合。
- 交付各系統**交換欄位與介接功能文件**說明。

# 捌、權限管理與資訊安全確認
- 帳號角色透過本院 **AD** 整合維護，並與 SSO 整合；提供使用者／群組與角色組合（role-base）之階層式權限授權。
- 操作稽核：資料新增／修改／刪除記錄最後異動帳號與時間；記錄登入、登出、登入失敗超過三次等事件（含帳號、IP、時間）。
- 使用者閒置達本院設定時間後自動強制登出；對外服務支援 SSL 等安全性規格。
- 依「資訊系統分級與資安防護基準」及本院 ISMS 辦理；配合弱點掃描與修補、防毒與資產機制；參與人員簽署保密切結書。
- 提供應用系統與資料庫之備份與回復，並配合本院災難復原演練。

# 玖、系統效能與服務水準
- 線上作業查詢回應時間不超過 **5 秒**（抽樣測試）。
- 系統可用率：接獲通知後 2 小時內連線處理，必要時 4 小時內到場，12 小時內回復正常運作。
- 提供系統備援與故障回復能力；保固期滿日前如回應時間超過規範，於一個月內免費調整完成。
