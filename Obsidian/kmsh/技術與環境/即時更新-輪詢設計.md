# 即時更新 — 定時輪詢設計

> 問題：白板停在某畫面（如病室動態），後台已改跑馬燈/床位，護理人員沒按 F5 仍看到舊資料。
> 決議：採**前端定時輪詢 (polling)**，不引入 WebSocket/SignalR。背景與方案比較見下「為何選輪詢」。

## 為何選輪詢（非推播）
- 白板是**無人值守大螢幕、單向顯示**；輪詢**無連線狀態**，斷網下次輪詢自動恢復，免寫 WebSocket 重連。
- 內網、資料量小、更新頻率低 → 輪詢成本可忽略。
- 病室動態本來就要輪詢院方 API（[[Board_ER]] ~8.7s、需快取），自建資料**併入同一套輪詢**即可。
- 不需 F5：輪詢取得新資料 → 更新 React state → 自動 re-render，只重繪變動處（React diff），不閃爍。
- 現況技術相符：前端為純 `fetch` service ＋ hook（`useClock` 的 `setInterval` 模式）、React 19、無 React Query → **零新依賴**即可實作。

## 核心設計：版本戳 + 分層頻率

### 1. 版本戳（避免每輪都拉整包）
不要每 N 秒重抓所有資料。改為輪詢一支**極輕的版本端點**，版本沒變就不動，變了才拉該類別完整資料 → 絕大多數輪詢只傳幾 bytes。

- **推薦：聚合版本端點** `GET /api/Board/{unitCode}/versions`
  一次回所有類別的版本 map，前端一次輪詢即知哪些類別變了，再分別重抓：
  ```json
  { "marquee": 1718690000, "bulletin": 1718689000,
    "census": 1718690100, "marker": 1718690100, "contact": 1718600000 }
  ```
- 版本值來源（二擇一）：
  - **A. 各表 `MAX(UpdatedAt)`**（需被白板讀的表都有 `UpdatedAt`；schema 已有 `PatientCensus.UpdatedAt`/`UnitInfo.UpdatedAt`，其餘待補）。
  - **B. 集中 `DataVersion` 表**（UnitCode, Category, Version），後台任何 CRUD 後 `Version++`。寫入點明確、查詢最省，**建議優先 B**。

### 2. 分層輪詢頻率 — ★各項目輪詢時間記錄（待院方確認）
> 此表為「日後與院方資訊單位確認」的依據。**現值**＝目前實際碼值（`React/src/config/pollingConfig.js`，code 為準）；**建議區間**＝設計建議；**狀態**＝是否已落地。確認後如需調整，改 `pollingConfig.js` 一處即可。

| 項目 | 現值 | 建議區間 | 狀態 | 常數 / 備註 |
|---|---|---|---|---|
| 時鐘 | 1s | 1s | ✅ 已落地 | `useClock`（前端自算，無 API）|
| 跑馬燈 | **30s** | 30–60s | ✅ 已落地 | `MARQUEE_MS` |
| 佈告欄 / 公告 | **60s** | 30–60s | ✅ 已落地 | `BULLETIN_MS` |
| 病床動態 / 病人註記 | — | 15–30s | ⬜ 待開發 | 建議 `CENSUS_MS=20s` |
| 急診檢傷 / 大量傷患 | — | 10–15s | ⬜ 待開發 | 建議 `TRIAGE_MS=12s`，新病人要快 |
| 值班/聯絡/避難圖 | — | 30–60s | ⬜ 待開發 | 變動少 |

> 待向院方確認：各項可接受的「最舊資料延遲」上限，據以定案各值；院方 API（如 Board_ER ~8.7s）另需後端快取，輪詢頻率不得低於快取 TTL。

## 前端架構
- **集中式版本輪詢**：一支 `useBoardVersions(unitCode)` 統一輪詢聚合版本端點（單一 timer）；各分頁訂閱自己關心的 category，版本變了才各自重抓資料。避免「每分頁各開 setInterval」造成多 timer 與請求齊發。
- 通用 `usePolling(fetcher, {intervalMs, deps})` hook（仿 `useClock`）：進畫面先抓一次、`setInterval` 重複、`useRef` 保存最新 fetcher、unmount `clearInterval`。
- React state 更新只重繪變動處；資料結構盡量沿用既有（如 ER `ShiftStaff`），兩邊一起換。

## 韌性 / 最佳化
- **斷線**：輪詢失敗**保留舊資料**並標 `stale`，畫面角落顯示「連線中斷，顯示為最後更新內容」；恢復後自動更新。
- **退避 (backoff)**：連續失敗時間隔加倍至上限（如 30s→60s→120s），成功後回正常頻率，避免狂打。
- **抖動 (jitter)**：多台白板開機時間相近，輪詢加 ±隨機偏移（如 ±2s）避免同秒齊發。
- **後端快取**：院方 API（Board_ER 慢）後端快取數秒、多台白板共用；前端輪詢打的是快取，不直接壓 HIS。
- **可見性**：白板常開不休眠，可不處理；若觸控切分頁，非當前分頁可降頻/暫停（`visibilitychange` / 分頁 active 狀態）。

## 後端配合（待 schema 建表後）
- 各會被白板讀的自建表補 `UpdatedAt`，CRUD 時更新（或改用 `DataVersion` 表集中記版本）。
- 新增聚合版本端點；既有 `TextController`/`ContactController`/`EvacuationController` 可先各加 `/version`。
- 院方 API 轉接層加短 TTL 快取。

## 落地順序
1. ✅ **已落地**：通用 `usePolling` hook，把跑馬燈/公告接成自動更新（純定時重抓，不需版本端點）。
2. 再加聚合版本端點 + `useBoardVersions`，升級為「版本變才拉」省頻寬。
3. 病室動態接 HIS/自建 census 後，納入同套輪詢。

## 已落地實作（第 1 步，純前端）
| 檔案 | 角色 |
|---|---|
| `React/src/config/pollingConfig.js` | 輪詢間隔常數（`MARQUEE_MS`=30s、`BULLETIN_MS`=60s）|
| `React/src/hooks/usePolling.js` | ★通用輪詢 hook：mount 先抓→`setInterval`→unmount 清除；失敗保留舊資料只標 `stale` |
| `React/src/hooks/useMarquee.js` | 跑馬燈改用 `usePolling`（四板共用，一處生效）|
| `React/src/hooks/useBulletin.js` | 公告共用 hook（`Promise.all` 抓 unit+hosp、排序）|
| `React/src/pages/boards/{ER,ICU,OR,W52}/tabs/BulletinTab.jsx` | 四板改用 `useBulletin`，移除各自重複的 fetch |

> **開發慣例**：之後白板要顯示、會變動的資料一律用 `usePolling`（或其衍生 hook），間隔取自 `pollingConfig.js`，勿 mount 只抓一次。Layout 層資料持續輪詢；分頁資料隨 mount/unmount 自然啟停。
