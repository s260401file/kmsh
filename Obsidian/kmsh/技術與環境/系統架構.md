# 系統架構

> 由實際程式碼分析得出（`C:\WorkDir\Nursing Whiteboard`）。

## 三個程式碼庫
| 角色 | 路徑 | 技術 | 部署到 IIS |
|------|------|------|-----------|
| 後端 API（含後台資料） | `…\API` | C# / .NET 8 MVC | 站台 `kmsh-api`（:5100）|
| React 前端（白板＋後台） | `…\React` | React / Vite | 站台 `kmsh-whiteboard`（:80）|
| html_demo | `…\html_demo` | 靜態 HTML/JS/CSS | 不部署（早期示意，見 [[前端策略]]）|

- 資料庫：**Microsoft SQL Server Express**。
- 規格要求：.NET 8 以上、IIS 10 以上、SQL Server 2022 以上、MVC、UTF-8、AD 帳號整合。

## React 應用內容
- 4 白板（巢狀路由＋分頁）：`/w52`、`/icu`、`/or`、`/er`
- **後台 `/admin`**：`AdminPage.jsx`，受 `AuthContext` 登入保護（`ProtectedRoute`）
- `services/`：以**相對路徑 `/api/...`** 呼叫後端（同源），目前有 `textApi`、`contactApi`、`evacuationApi`、`marqueeApi`

## .NET API 控制器（現況）
- `TextController`（跑馬燈、佈告欄）
- `ContactController`（值班人員、常用電話）
- `EvacuationController`（避難圖圖片、設備、聯絡）
- 待長出：床位/病人、檢查會診、手術、排班、醫師查房、交班、團隊、抗生素…＋接[[_院方API總覽|院方 API/HIS]]

## 院方資料主機（88 / 84，皆民生 VM）
> 高榮 HIS 的 DB 在**高榮**；以下兩台都是**民生醫院的 VM**。
| 主機 | 角色 | 備註 |
|------|------|------|
| **10.20.111.88** | **高榮開放區** | 高榮開放給民生的資料落在此；《醫療系統資料字典》81 表來源（`/REPORTS/quicksearch`）|
| **10.20.111.84** | **民生 copy 區** | 民生資訊人員因 88 作業量大，建此台**排程 copy 88 的資料**；[[Board_ER]] API（`:8088`）在此 |

- **現況**：84 的**排程同步異常**（資料停更，第5次會議）。
- **可能調整**：**不排除讓建置方直接存取 88**（繞過 84 的 copy）。

## 資料流
```
高榮 HIS（DB 在高榮）
   │ 開放部分 ＝ 81 表報表庫
   ▼
[88 高榮開放區] ──排程copy(異常)──▶ [84 民生copy區｜Board_ER API:8088]
   └─（可能改：直接存取 88）─┐         │
                              ▼         ▼
                   .NET API（+自建後台資料｜SQL Express）─→ React 白板（/w52 /icu /or /er）
自建後台輸入 → React 後台 /admin ┘                        └→ html_demo（之後同步）
```
> 註：SQL Express 是**本系統自建後台資料**用；高榮臨床資料的 DB 在高榮（經 88/84 取得）。
