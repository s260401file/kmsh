# 前端策略（html_demo vs React）

## 兩套前端的關係
| | html_demo | React |
|---|---|---|
| 角色 | 最早的**靜態示意/雛形** | **現行主力**（白板＋後台）|
| 技術 | 純 HTML/JS/CSS | React/Vite |
| 部署 | 不部署 | IIS `kmsh-whiteboard` |

## 工作政策（目前）
- **一律先改 React**，html_demo **之後同步**成相同樣貌。
- 例：ER 檢傷 A/B/C、OR 刀房改號、ER 三班面板 → 已先在 html_demo 改、再同步 React（或反之），最終兩邊一致。
- 之後若 html_demo 不再需要，可考慮停用；目前先維持同步。

## 提醒
- 同一份「資料結構」盡量共用（如 ER `ShiftStaff`），方便日後接 API 兩邊一起換。
- 形狀/樣式邏輯已抽共用模組（React `utils/flagShapes`）。
