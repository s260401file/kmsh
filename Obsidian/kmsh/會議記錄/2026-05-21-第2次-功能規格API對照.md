# 第2次｜功能規格 × API 對照討論

> 2026-05-21（週四）16:00 · Meet · 依《功能規格_API對照討論_20260519_Kevin.doc》· 記錄：邱文政 · 下次：下週四 14:00

## 與會
院方各站護理長（ER/ICU/OR/一般病房）；建置方 林經理、Kevin、邱文政。

## 會議目標
逐項檢視 4 站約 39 項規格與實作現況，分類：A 可直接開發 / B 需確認 API / C 需後台自建 / D 需討論定義；產出第一版「需求確認書」。

## 四、重要決議
- ⚑ **以「需求確認書」為最終驗收版本**（雙方簽名），需確認合約是否有此條款（同高市聯醫做法）。
- ⚑ **規格書與現場不符以需求確認書為準**（例：ER 規格寫第一/二診療區，民生現場無此區分，以平面圖為主）。
- ✓ 資料來源原則：HIS 有 → 截圖標註 → 邱主任申請 API；HIS 無 → 後台自建或前端計算。
- ✓ 效能：手術來源顏色等由 API 帶入而非後台每日手動，降低護理負擔。
- ⓘ API 申請耗時，資料就緒前先以空白欄位呈現、後續補。

## 六、各單位逐項（摘要結論）
### 6.1 一般病房
- 護理長/主任=後台自建；跑馬燈分類（護理站/院方）後台加分類欄；病人詳細彈窗（A）；**病患旗標 9 項**需確認 HIS `getBedList`（B）；床數統計/床位動態/檢查會診篩選=前端計算（A）；管路統計（B）；手術欄位完整性（B，`qrynonexschlist`）；檢查會診 24h 移除（待確認後端或前端過濾）；護理人員負責床位 `bedNurseAssignApi`（A）；排班班別/應變編組（B，OAS NAME/PE_GROUP）；點班（D）；醫師負責床位（B）；查房時間表 `doctorRoundApi`（B）；避難圖 `evacPlanApi`（A）；護理交班=自建（C）；照護團隊=待討論名單來源（D）。

### 6.2 ICU
- 病人彈窗（A，內容各站護理長提供）；旗標 9 項（B）；床數統計（A）；**疾病嚴重程度 A/B/C 顏色**（B，高榮有 APACHE 畫面、已截圖待 Kevin 比對）；管路改 icon（A）；抗生素改點選床位顯示（A）；抗生素欄位 firstDoseTime（B，`hisIcuAntibioticApi`）；當日/前後3日手術（B，`hisSurgeryApi` 能否以 ICU 床號＋日期範圍）；檢查會診（A）。

### 6.3 OR
- 刷手/流動護理師顯示（A）；手術來源顏色（B，建議 API 帶入）；手術詳細彈窗（A）；手術統計（B，與來源連動）；手術派班 3 班分組＋統計（A）；特殊交班業務流程（D，需設計填寫/傳遞/通知）。

### 6.4 ER
- 床位分區（A，規格區域名與現場不符，以需求確認書/平面圖為準）；平面圖（護理長下週提供）；急診統計細項（B）；病患旗標 留觀/住院含床號/死亡/MBD/AAD/轉院含醫院（B，截 HIS 申請）；大量傷患清單 `mciPatientApi`（A）；大傷旗標（B）。

- 7.1 ER 規格 7 區 vs 現場（第一/二留觀、急救，無分第一/二診療）→ 以需求確認書為準，上線移除不適用區。
- 7.2 ICU APACHE 分級截圖已上傳，Kevin 比對 API 欄位後申請。
- 7.3 OR 特殊交班：`opNotes` 僅一般備註，不符業務流程，待釐清填寫/傳遞/通知。
