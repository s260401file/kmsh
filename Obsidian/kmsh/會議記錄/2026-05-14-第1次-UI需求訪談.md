## 三、會議目標
- 依四套既有操作手冊框架逐站確認 UI 需求與資料來源
- 盤點高榮 HIS 現有 API 可提供哪些資料，缺漏列入後續申請清單
- 確認 9 月驗收前「第一版可上線範圍」（聯醫版本為基礎再擴充）
- 確認後續會議頻率與線上協作方式

## 四、重要決議
- ⚑ **9 月前驗收為硬性時程**；共識「先求有，再求好」，第一版以聯醫舊版功能為基礎，9 月後逐步擴充。
- ⚑ **驗收標準：合約所列功能必須 100% 完成**；資料取得困難屬建置方應控管的風險，不得因此降低驗收標準。
- ⚑ **資料來源原則**：HIS（高榮）有資料 → 資訊室向總院申請開放 API；HIS 無資料 → 後台手動建置。「不為了做資訊而做資訊」。
- ⚑ 各站護理長 5/21 前提供「高榮 HIS 截圖」對照表（資料畫面＋對應白板位置）。

## 五、各站 UI 討論摘要
### 5.1 一般病房（5B 示範）
- 床位依「實際病房位置」排列（非床號順序）；空床仍顯示。
- 性別配色：粉紅=女、粉藍=男；同房依床號排列。
- 床位顯示：床號＋姓名＋主治醫師（姓名下方）；護理師資訊改分頁查看。主治醫師 API 自動帶入。
- 照護提醒（狀態註記，約 8 項）：過敏（藥物過敏特別重要）、癲癇、隔離、DNR、舒服、當日欲出院、高危跌、出服。版面有限，優先 80/20 高頻項目。
- **運送等級（取代原紅黃綠）**：高榮 HIS 第二頁有運送等級；A=紅/B=黃/C=綠（不沿用原圖示），協助工友推送掌握需求等級。
- 待確認：他站候床訊息（ER/ICU 候床數）、APACHE 分數（ICU 提）、約束/Order（聯醫無，康仲和精神科以勾選呈現）、住院天數（交班才能取得）。

### 5.2 ICU
- 管路類型 NG/POLY/ENDO… 依 HIS 自動帶入，最多約 3 管；顯示置入時間＋預計換管日（如 CVP 14 天提醒）。
- 抗生素：開始/結束時間、藥品名；須向總院申請開放。
- 床位分科別顏色（內/外科），與 ER 統一配色；顯示床號＋姓名＋主治醫師（VS）；點擊展開病人卡。

### 5.3 OR
- 共 7 間 OR（OR1~OR7）；版面可參考實際刀房配置，資料不足則依序排列。
- 每房顯示：姓名、術式、主治醫師。刷手/副手護理師從派班系統取得（高榮目前無此 API，列後續申請）。
- 統計：今日總刀數、進行中、已完成。手術備註欄＝OR 專屬，後台維護。

### 5.4 ER
- 醫師：急診只有白班、夜班各一位（不分科別），放版面前面以下拉選擇。
- 會診醫師：依科別建清單，下拉每日選當日值班醫師；後台維護科別/醫師/電話。
- 照服員：白/夜班各一名，後台維護、前台下拉，以 12 小時為單位。
- 床位依「區域」分配（非位置式），急診人數浮動。
- 檢查/會診欄位：床號、病歷號、姓名、科別、預約時間、狀態。

## 七、技術/環境
- Windows Server 2022、SQL Server 2022（院方授權）；VM 資源緊張，需提供硬體規格。
- 強制 HTTPS(443)，內網仍綁 SSL。高榮 API 需 IP 白名單＋KEY。
- 即時呼叫 API 優於定期挖 DB。建置方初估 API 可滿足約 **70%**，其餘 30% 需申請。
- 申請流程：建置方需求單 → 資訊室向高榮 → 總院寫轉換程式 → 提供 API。
- 溝通：技術群組／UI 需求群組；改用 Google Meet；圖文以「截圖＋標註」PPT 共享。
