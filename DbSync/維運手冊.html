1這是什麼

把真實 DB2（高榮 HIS）中白板需要的表，每幾分鐘增量同步到 SQL Server 的 DB2_DUMP 庫，讓白板前端讀得到近即時資料。

定位＝並存分工：資訊室原本的整包 dump（Java，約 30 分鐘、人工手動）照常跑；DbSync 只負責白板用到的少數表、每 5 分鐘增量，讓白板不必等整包 dump。兩者都寫入源真值、交易短，最後寫入者正確，不衝突。

2執行方式與退出碼

DbSync.exe --tier fast     :: 白板子集（排程每 5 分鐘）
DbSync.exe --tier slow     :: 低頻/對帳（排程每 30 分鐘或每晚）
命令列參數說明
--tier fast|slow要跑哪一層（必填，預設 fast）。哪些表屬哪層看 appsettings 的 Tier
--inspect-keys唯讀診斷：印出各表在 DB2 的主鍵/唯一索引，供校正 KeyCols（不做同步）
--reprocess-hours N忽略浮水印，強制從「N 小時前」重新撈（回補漏資料用）
--no-pause跑完不暫停（排程情境用）
--pause-seconds N雙擊執行時跑完停留 N 秒（預設 15）後自動關閉
退出碼意義（供排程器判讀）
0全部成功（或本輪因上一輪未跑完而跳過）
1有表失敗或發生例外
2參數錯誤

視窗行為：雙擊 DbSync.exe 或 run-test.bat 會跑完停住顯示結果（15 秒後自動關）；由排程/終端機執行則不暫停，看 logs\ 即可。

4部署（VM，須同時連得到來源 DB2 與目標 SQL Server）

dotnet publish -c Release -r win-x64 --self-contained true -o publish
  1. 把 publish\ 整包複製到 VM。
  2. 由 appsettings.sample.json 複製出 appsettings.json，填入實際兩端連線帳密。
  3. 依第 5 節設定要同步的表。
  4. 依第 8 節在工作排程器建兩個工作。

5設定檔 appsettings.json

{
  "Db2ConnectionString": "Server=DBGW1.vghks.gov.tw:50000;Database=DBDSNP2;UID=帳號;PWD=密碼;Connection Timeout=8;",
  "SqlConnectionString": "Server=10.20.111.84;Database=DB2_DUMP;User Id=帳號;Password=密碼;Encrypt=False;TrustServerCertificate=True;",
  "StateDir": "state",
  "LogDir": "logs",
  "CommandTimeoutSeconds": 300,
  "Tables": [
    { "Schema": "AM", "Name": "HCASE_4A0", "Tier": "fast", "Mode": "replacekey",
      "WatermarkCol": "ZHCASE", "KeyCols": ["HHISNUM","HCASETYP","HCASENO"], "Filter": null, "Enabled": true }
    /* ...其餘表... */
  ]
}

每張表（Tables 內一筆）欄位：

欄位說明
Schema / Name表的 schema 與表名（來源與目標同名，如 AM / HCASE_4A0）
Tierfast（每 5 分）或 slow（每 30 分/每晚），對應排程
Mode同步方式：replacekey（首選）/ incremental / append / full，見第 6 節
WatermarkCol異動時間欄（HIS 多為 Z 開頭）。replacekey/incremental/append 必填；full 不用
KeyCols鍵欄位。replacekey＝案群組鍵（不需唯一）；incremental/append＝須唯一鍵
Filter可選的 WHERE 條件字串（不含 WHERE 兩字）；null＝全部
Enabledfalse 可暫停此表（不同步），無需刪除設定

6同步模式 Mode 怎麼選

Mode做法需唯一鍵何時用
replacekeyZ* 找出有異動的「案群組」，把目標該群組整組刪除後、以來源現況重寫（單一交易）否首選。HIS 表在 DB2 多半沒宣告唯一鍵，用這個最安全
incrementalZ* 撈異動列，以鍵 upsert（有則更新、無則新增）是確定該表 KeyCols 唯一時
append同上但只 INSERT、不更新既有列是純新增、不回頭改的表（如日誌類）
full全表拉進暫存表，整列雜湊比對 upsert＋刪除來源已無的列是小表或低頻對帳（建議掛 slow）
經驗法則：不確定就用 replacekey。它免唯一鍵、且目標群組永遠與來源一致。
唯一限制：整個案「從來源消失」（跨群組刪除）增量偵測不到，需靠 slow 層 full 對帳補上。

7【重點】如何加開一張資料表

情境範例：白板新功能要用到護理站主檔 AM.HNURSTA_4A0（表名為示意，實際依 HIS）。

步驟 1 — 先確認目標庫 DB2_DUMP 已有這張表

本工具以「目標表的欄位」為準去抽取來源（GetColumns 讀目標 sys.columns、RecreateStaging 由目標結構複製暫存表）。所以 DB2_DUMP 必須先有 AM.HNURSTA_4A0 這張表，且欄位名稱與來源一致（要同步的欄位，目標要有）。

  • 若目標還沒有 → 先在 DB2_DUMP 依來源結構建好表（欄位名/型別比照來源）。
  • 只想同步部分欄位 → 目標表只建那些欄位即可（工具只撈目標有的欄位）。

步驟 2 — 查來源的鍵與浮水印欄

DbSync.exe --inspect-keys

在 log 看 AM.HNURSTA_4A0 那行：

  • 有印出 PK/UNIQUE → 可用 incremental，KeyCols 填該鍵。
  • 印出「DB2 無宣告 PK/唯一索引」→ 用 replacekey，KeyCols 填能代表「一筆案/一組」的欄位（如 HHISNUM 或 HHISNUM+HCASENO，允許重複、不需唯一）。

再找該表的異動時間欄（WatermarkCol）：HIS 慣例多為 Z 開頭（如 ZHNURSTA）；可問 HIS 端或查該表結構。

步驟 3 — 在 appsettings.json 的 Tables 加一筆

{ "Schema": "AM", "Name": "HNURSTA_4A0", "Tier": "fast", "Mode": "replacekey",
  "WatermarkCol": "ZHNURSTA", "KeyCols": ["HHISNUM"], "Filter": null, "Enabled": true }
  • 只在白班尖峰時段要新鮮 → Tier 設 fast；純參考/量大 → 設 slow。
  • 想先只同步某病房 → Filter 可填如 "HNSTATN = 'W52'"（純 WHERE 條件、不含 WHERE 字）。

步驟 4 — 手動試跑一次，看 log

DbSync.exe --tier fast          :: 或直接雙擊 run-test.bat

到 logs\dbsync-fast-YYYYMMDD.log 確認出現類似：

AM.HNURSTA_4A0｜replacekey 受影響案群組 N 列：刪除 x、寫入 y，浮水印 → 2026-07-07 09:15:00.000。
  • 撈到筆數合理、無 ERROR → 成功。
  • 首次執行：若目標表已有資料，會以「目標現有最大 Z*」起算（不會整表重灌）；若目標是空表，會從 1900 全撈（首撈較久，正常）。

步驟 5 — 完成

排程用的是同一支 DbSync.exe --tier fast，無需改排程，下一輪就會自動帶到新表。到 DB2_DUMP 查 SELECT COUNT(*) FROM AM.HNURSTA_4A0 確認資料進來。

常見錯誤

log 訊息原因 / 處置
目標找不到表 AM.HNURSTA_4A0 或無欄位目標 DB2_DUMP 還沒建這張表 → 回步驟 1
... 為 replacekey 模式但未設定 WatermarkCol/KeyColsappsettings 少填 → 補上

8Windows 工作排程器設定

建兩個工作，分別執行：

  • 工作 A：DbSync.exe --tier fast，觸發程序「重複間隔 5 分鐘、持續無限」。
  • 工作 B：DbSync.exe --tier slow，觸發程序「重複間隔 30 分鐘」（或設每晚一次）。

建議勾選：

  • 「不論使用者登入與否皆執行」。
  • 「如果工作已在執行中，下列規則生效 → 不要啟動新的執行個體」（與程式內建 Mutex 雙重保險，避免重疊）。
  • 「起始位置」設為 DbSync.exe 所在資料夾（確保讀到同目錄 appsettings/state/logs）。

9日常維運

  • 看每日 log：logs\dbsync-fast-YYYYMMDD.log。每輪有 ===== 開始/結束 ===== 與每表一行結果。
  • 判斷健康：結束行 成功 N／N，失敗 0 即正常；出現 ERROR 或 失敗 >0 需查。
  • 浮水印：state\watermarks-*.json 記每表進度；正常無需手動碰。
  • 磁碟：log 每日一檔會累積，可自行加保留天數清理（例：保留 30 天）。

10疑難排解

問題處置
DB2 連不上確認 VM 到 DBGW1.vghks.gov.tw:50000 防火牆已開、帳密正確；log 會顯示連線例外。可先 DbSync.exe --inspect-keys 測連通
某表一直失敗看該表 log 的錯誤訊息；常見為目標表結構與來源欄位不符、或 WatermarkCol 欄名錯
漏同步/資料不對，要回補DbSync.exe --tier fast --reprocess-hours 24（強制重撈近 24 小時，忽略浮水印）
要某表整個重來編輯 state\watermarks-{tier}.json 刪掉該表那一行 → 下次以「目標現有最大值」重起；或先清空目標表再跑（會全撈）
暫時停掉某表該表 "Enabled": false，不必刪設定
兩輪跑太近會不會撞不會。每層別具名 Mutex（Global\DbSync_{tier}），上一輪沒跑完，本輪直接跳過（log 顯示 [skip]）

11安全與注意事項

  • appsettings.json 含兩端帳密，勿上傳版控（已在 .gitignore）；VM 上請限制檔案存取權限。
  • 連線值一律走參數/SqlBulkCopy，無 SQL Injection 風險；SQL 中的欄名來自系統目錄、非使用者輸入。
  • DbSync 對來源 DB2 只做 SELECT（唯讀）；只有目標 DB2_DUMP 會被寫入。
  • 暫存表 dbo._stg_* 每輪用完即刪；若程式異常中止偶有殘留，可安全手動 DROP。
提醒：本手冊不記載實際帳號密碼；連線資訊由資訊室另行保管，僅維護於 VM 上的 appsettings.json。
